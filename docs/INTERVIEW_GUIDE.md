# 小慕问卷面试讲解指南

## 30 秒项目介绍

小慕问卷是我独立完成并部署的在线问卷平台，包含可视化编辑器、发布分享、公开填写和数据统计完整闭环。前端使用 React、TypeScript、Redux Toolkit 和 dnd-kit，后端使用 Express、JWT 与 PostgreSQL，部署在 Railway 和 Neon。项目还加入了 API 权限测试、GitHub Actions、请求追踪、输入校验和数据库索引。

## 5 分钟演示顺序

1. 使用 `demo_user` / `demo123` 登录，展示 JWT 登录态和问卷列表。
2. 新建问卷，说明新问卷自动带有 7 个默认组件。
3. 在编辑器展示组件配置、拖拽排序、隐藏、锁定、复制、撤销和重做。
4. 修改标题并发布，展示公开填写链接和二维码。
5. 在新标签页提交答卷，再返回统计页展示明细与图表。
6. 打开 GitHub Actions，说明每次推送都会自动执行 Lint、8 个测试和生产构建。

## 架构讲解

- 编辑器组件树由 Redux Toolkit 管理，`redux-undo` 保存历史状态。
- 题型采用配置表设计，将展示组件、属性面板和统计组件统一注册。
- Axios 拦截器负责携带 JWT，并统一解析 API 响应和错误提示。
- Express 负责鉴权、资源归属校验、参数校验和登录限流。
- PostgreSQL 存储用户、问卷和答卷；答卷写入与计数更新在同一事务中完成。
- Railway 负责应用部署，Neon 提供托管 PostgreSQL，GitHub Actions 负责持续集成。

## 常见追问

### 为什么使用 Redux？

编辑器涉及组件列表、当前选中项、复制内容和页面配置等跨区域状态。Redux 让左侧组件库、中间画布和右侧属性面板共享同一数据源，也便于接入 `redux-undo` 实现撤销重做。

### 如何避免越权访问？

服务端从 JWT 获取用户 ID，查询、更新、复制、删除和统计操作都同时校验问卷 ID 与所有者 ID。测试中使用两个账号验证其他用户无法修改或读取统计数据。

### 如何保证答卷数量准确？

PostgreSQL 模式下，插入答卷和重新统计 `answer_count` 在同一事务内完成，并对问卷行加锁，避免并发提交导致计数不一致。

### 做过哪些性能优化？

前端对列表、编辑器、统计页和填写页做路由懒加载，首屏主包从约 526 KB 降到约 284 KB。数据库针对问卷列表和答卷分页查询建立复合索引。

### 如何排查线上问题？

每个请求都带有 `X-Request-Id`，Railway 输出结构化日志，包括路径、状态码和耗时。错误日志通过请求 ID 与访问日志关联，同时不记录密码、JWT 或答卷内容。

### 当前还能如何扩展？

可以将单实例内存限流迁移到 Redis，增加团队协作与问卷模板，使用游标分页替代深页 OFFSET，并将前端升级到 Vite 以进一步改善构建速度和依赖安全性。
